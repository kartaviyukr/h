# Фаза 6 — План: Корзина и дип-линки на сервисы доставки

> Статус: **ожидает подтверждения**. Код не пишется до утверждения этого плана.

## Цель фазы
По меню и сохранённому сравнению цен (Фаза 5) сформировать **корзину** у
выбранного провайдера и отдать **дип-ссылки**: на каждый товар (универсальные
URL продуктов) и, где возможно, агрегированную ссылку на готовую корзину/поиск.
Клиент сможет открыть приложение/сайт сервиса с заполненной выборкой.

## ⚠️ Реальность дип-линков (важно для дизайна)
- У сервисов доставки РФ **нет публичных задокументированных API «prefill cart»**.
  Универсальные ссылки на конкретные товары обычно работают; «корзина целиком»
  через URL поддерживается далеко не везде и не документирована.
- В этом окружении прокси отдаёт 403 на внешние сайты, поэтому проверять
  реальные ссылки/редиректы здесь нельзя; адаптеры конкретных сервисов —
  отдельные PR'ы в окружении с сетью.

Поэтому Фаза 6 строится как **расширяемая абстракция билдеров дип-линков**:
- Интерфейс `DeepLinkBuilder` (per-provider).
- `DefaultDeepLinkBuilder` — берёт `url` из `ProductOffer` (мы уже завели поле в
  Фазе 5) и формирует список ссылок на товары; для агрегированной ссылки —
  опционально шаблон (если задан у провайдера), иначе `null`.
- Боевые билдеры под Самокат/СберМаркет/Лавку/ВкусВилл — отдельные PR'ы.

## Поток
1. Берём последнее (или указанное) сравнение цен меню (`basket_quote`).
2. Из него выбираем корзину провайдера (запрошенный `provider` либо
   `cheapest_provider`).
3. Формируем список **матченных** позиций корзины (название, упаковки, цена,
   product_url). Ненайденные позиции пробрасываем отдельным списком, чтобы
   пользователь видел, что нужно докупить вручную.
4. Получаем `DeepLinkBuilder` для провайдера, строим `CartLink` (per-item URLs +
   опциональная aggregated URL).
5. Сохраняем `cart` (JSONB payload + provider + ссылка на quote/меню).
6. Отдаём в API.

## Модель данных
### carts
| поле | тип | примечание |
|------|-----|-----------|
| id | UUID PK | |
| user_id | UUID FK → users (cascade) | владелец |
| menu_id | UUID FK → menus (cascade) | |
| basket_quote_id | UUID FK → basket_quotes (set null) | источник цен |
| provider | text | код выбранного сервиса |
| total_rub | numeric | итог корзины |
| aggregated_url | text NULL | если билдер умеет |
| payload | JSONB | items[{name, offer_name, packages, cost_rub, url}], unmatched[] |
| created_at | timestamptz | |

(JSONB — для трассируемости; в будущем при необходимости нормализуем позиции.)

## Эндпоинты (под Bearer)
- `POST /menu/{menu_id}/cart` — body: `{provider?: str, quote_id?: uuid}`.
  Если `provider` не задан — берём `cheapest_provider` последнего/указанного
  сравнения. Если `quote_id` не задан — последнее сравнение. Возвращает `CartOut`
  с дип-линками.
- `GET /menu/{menu_id}/cart` — последняя сохранённая корзина для меню (404, если нет).
- `GET /cart/{cart_id}` — конкретная корзина (404 на чужую).

## Дип-линк билдеры
- `DeepLinkBuilder.build(provider_code, items: list[CartItem]) -> CartLink`
- `DefaultDeepLinkBuilder`:
  - per-item URL = `item.offer.url` (если есть).
  - `aggregated_url` = `None` по умолчанию; если в каталоге провайдера задан
    `aggregated_url_template` (Фаза 5+), подставляем коды/имена.
- Реестр: по `provider_code` возвращает специфичный билдер, иначе default.

## Тесты (CI, без сети)
- `cart_service`: построение корзины из basket_quote, выбор провайдера, передача
  ненайденных, расчёт total_rub из суммы matched items.
- `default deeplink builder`: формирует per-item urls из offer.url, aggregated=None.
- API: 200 + сохранение, GET-варианты, 404 на чужое/несуществующее, 401/403 без токена.
- conftest: добавить `carts` в TRUNCATE.
